# 配置文件仍然是唯一的事实来源

[English](0002-config-file-is-the-source-of-truth.md) | **简体中文**

控制台本可以把改动存进数据库、再覆盖到文件上，或者从一个序列化的结构体重新生成整份文件。
两条路都被否了：两个事实来源就需要合并规则，还会制造一类永久的「我的改动为什么没生效」
bug；序列化重写则会丢掉注释，而注释正写着每个字段存在的理由。所以控制台只是每个命令都在
读的那份 `config.toml` 的编辑器。它用 `toml_edit` 重写现有文档，保留注释、顺序和未知
字段；写之前校验整个文件；再通过临时文件加 rename 原子替换。表单加载后变过的文件，绝不
被覆盖。

## 考虑过的选项

- 用 `Serialize` 从 `Config` 重新生成：这些类型目前没有 `Serialize`，而且重写会把默认值
  一股脑写进手写的配置文件里。
- 数据库覆盖层：做起来快，但运维得知道每个字段是哪一层说了算。

## 后果

- 密钥没法经过表单往返。凭据来源就显示成来源；新增或轮换 key 只写操作系统的凭据库。
- 所有写入方 —— 控制台、编辑器、将来的 `lgw` 命令 —— 都走同一条「先校验、再应用」的
  路径，所以只有一套规则要测、要写。
