# 03：引入 Runtime 快照与请求级配置

**要构建什么：** 行为不变，只做一处结构性改动：启动时进程构建一份不可变的 Runtime 快照，装下所有由配置派生的东西 —— 解析好的路由与别名、provider 视图、policy 数值与超时、配置价种子、档位表、探测集合、上游客户端配置、解析后的 local_key 状态。每个请求和每次探测在准入时捕获一次快照并用到结算，这样以后一次应用可以发布新快照而不碰已经在跑的工作。

**依赖：** 02（把 HTTP 层从 Gateway 中分离）。

- [ ] 请求处理从准入时捕获的快照读配置；估算、档位和结算用同一份快照。
- [ ] backend 接口不再借出由 gateway 持有的配置引用。
- [ ] 测试在流式请求在途时发布第二份快照：在途请求用第一份完成，之后开始的请求用第二份。
- [ ] 只有一份快照时启动行为不变；轮询器和探测也用同样的方式捕获。
- [ ] `cargo test`、`clippy --all-targets -- -D warnings`、`fmt --check` 通过。
