# light-ai-gateway 的浏览器控制台

[English](SPEC.md) | **简体中文**

**状态：** 实现规格。相关决定：ADR-0001（控制台是只绑 loopback 的运维界面）、ADR-0002
（配置文件是事实来源）、ADR-0003（应用是原子的，运行中的请求保留自己的快照）、ADR-0004
（控制台内置在二进制里）。契约：`docs/web-ui.md`。领域语言：GLOSSARY.md。

## 问题陈述

配置网关意味着编辑 TOML 文件、跑 CLI 命令。文件是运维一周里最慢的那一环：拼错一个地方，
要等下一条命令失败才会发现；改动不重启进程就应用不了；而重启会丢掉那一刻正在流式传输的
每个请求。想知道池子在干什么，就得跑好几条命令、读终端表格；比较一周的花费、或者找出某
个出错的请求，得手工重拼查询。运维没有一个统一的地方：既能看池子、回答用量问题，又能
接受一次配置改动、并用上网关自己那套校验。

## 方案

`lgw serve` 在同一个监听器、同一台机器上还提供浏览器控制台。它显示看板、用量和花销、最近
的请求、价格和漂移、诊断结果，以及凭据来源；它提供 CLI 有的那些动作；还能用表单编辑
`config.toml`。保存的改动会写回同一个文件，并应用到运行中的进程，不丢掉在途请求：请求
继续用它启动时那份运行时快照，新请求看到新快照；只有会给进程重新接线的设置才等重启（并且
会说清楚）。控制台没有登录，因为它只回应 loopback 对端，而且防着另一个浏览器标签页里的
页面。

控制台是单个运维的工具，不是客户端 API。OpenAI 兼容的 `/v1` 接口、它的鉴权和 JSON 契约
都不变。文案在英文和简体中文之间切换，默认浅色、带夜间模式；所有东西都随二进制发布，
没有 Node 构建步骤。

## 用户故事

### 访问与安全

1. 作为运维，我希望跑完 `lgw serve` 后控制台就在网关自己的地址上，以便我不需要第二个
   进程或端口。
2. 作为运维，我希望控制台只回应 loopback 对端，以便把代理监听器暴露到网络上时不会顺带
   暴露配置编辑。
3. 作为运维，我希望控制台页面和动作不需要登录、cookie 或会话就能用，以便没有第二份凭据
   要管。
4. 作为运维，我希望另一个浏览器标签页里的页面改不了配置，以便访问一个不可信的页面
   花不掉我的额度。
5. 作为运维，我希望控制台拒绝 `Host` 不是 loopback 监听器的请求，以便 DNS rebinding
   到不了它。
6. 作为运维，我希望监听地址不是 loopback 时，控制台仍能通过 `127.0.0.1` 访问，以便
   我日常的本地工作流照常能用。
7. 作为运维，我希望每个控制台响应都带严格的内容安全策略、禁止被其它页面嵌入、禁止
   缓存，以便别的站点既嵌不进也缓存不了控制台页面。
8. 作为运维，我希望控制台不碰 `/v1`，包括它的 `local_key` bearer 规则，以便现有客户端
   和挂件完全察觉不到控制台。
9. 作为运维，我希望控制台从不显示、返回或记录 provider key 或 `local_key` 的值，以便
   屏幕共享或日志文件都泄不出一份凭据。
10. 作为运维，我希望非 loopback 对端从每一条控制台路径都拿到同样的 404，以便这个
    界面不会自己暴露自己。

### 看板

11. 作为运维，我希望有一个页面列出每个账号及其 provider、标签和状态，以便一眼就能看到
    整个池子。
12. 作为运维，我希望看到每个账号的 Covered 窗口，以及每个窗口的已用量和上限，以便分得清

13. 作为运维，我希望看到每个账号的 Metered 余额或钱包，以便我知道还剩多少真钱。
14. 作为运维，我希望每个窗口都有重置倒计时，以便不用在脑子里算时间戳就知道账号什么时候
    回来。
15. 作为运维，我希望 Covered 的额度和 Metered 的钱在视觉上、文字上都分得清、永远不会
    合并，以便消耗订阅绝不会被误认成花现金。
16. 作为运维，我希望过期的读数被标成 stale 并显示它有多旧，绝不显示成零，以便一次失败

17. 作为运维，我希望 Disabled、Draining 或 Parked 的账号显示它的状态、最后一次错误和

18. 作为运维，我希望每个窗口在整个池子上的库存占比，以便能在每个账号旁边判断整个池子。
19. 作为运维，我希望一眼能看到关键体征（每分钟请求数、在途请求数、p95 TTFT、最近的
    错误、缓存命中率），以便不离开页面就能分清健康还是吃力。
20. 作为运维，我希望看板按定时器刷新、不探测 provider，以便盯着它看不花额度。
21. 作为运维，我希望有个刷新按钮和一个全部探测动作，以便怀疑上次读数太旧时能强制要一份
    新的。
22. 作为运维，我希望看板上有一份价格漂移摘要，以便一次悄悄发生的重新定价会出现在我第一
    眼看的地方。
23. 作为运维，我希望一个账号都没探测过时，看板也渲染最后已知状态、显示「还没探测过」，

24. 作为运维，我希望随时间变化的花费拆成 Covered 和 Metered，以便能看出一次改动是让

25. 作为运维，我希望有 token 数（输入、输出、缓存）和缓存命中率，以便能盯住换号毁掉的

28. 作为运维，我希望有 24 小时、7 天、30 天、90 天和全部这几种范围，以便常用的对比

29. 作为运维，我希望金额总计保持账本精确的 Decimal 精度、按币种分开，以便面板和账本对

## 实现决定

### 模块形态

- HTTP 层与网关分开：一个模块组装 router、鉴权中间件和监听器；代理处理器、冻结的
  `/v1` usage 处理器和控制台路由彼此相邻，而不是挤在一个文件里。
- CLI 被拆成按命令划分的模块，共用配置路径解析和调色板处理。这是一次机械搬迁，先做，
  用 `git mv`，每步之后测试套件都保持绿色。
- 新的运行时模块持有不可变的运行时快照、应用/重新加载引擎和文件监视器。
- 新的 operations 模块持有 CLI 和控制台共用的动作和查询：看板数据、用量聚合、最近的
  请求、价格、诊断、探测、账号启用/停用、凭据列出/测试/移除。控制台没有自己的规则。
- 新的 console 模块持有页面、自动刷新的局部模板、动作结果片段、英文/中文文案目录、
  SVG 图表和内嵌资源清单。
- 现有的 gateway 模块保留实时池子、学到的价表、探测集合、档位表和区间账本，只在快照
  不拥有某个值时获得内部可变性。

### 运行时快照

- 运行时快照是一份由配置派生、不可变的视图，请求或探测从准入到结算都用它：解析好的
  路由和别名、provider 配置、policy 值和超时、配置价的种子值、档位表、探测集合、
  HTTP 客户端配置，以及解析好的 `local_key` 状态。
- HTTP 处理器在准入时取一次快照，然后一路传下去；后端接口不再把网关持有的配置引用借
  出去。
- 结算用的是准入这次尝试的那份快照，所以估算、档位和成本永远来自同一份配置。
- 快照通过一次原子指针交换发布；只要还有请求持有旧快照，它们就继续活着。

### 配置：文件就是事实来源

- `Config` 仍然只负责解析和校验，不会被序列化回去。改动是应用到现有的 TOML 文档上，
  保留注释、键顺序和未知字段，结果再交给每个命令都在用的同一段代码解析、校验。
- 草稿配置是已知区段的结构化表单内容，加上它构建时所依据文件的指纹。服务端把草稿
  配置应用当前文档上；表单不拥有的字段原样不动。
- 校验错误变成结构化值，带稳定的 code、字段路径和参数。CLI 继续渲染同样的英文消息；
  控制台则从语言目录渲染它们。
- 流水线顺序是：解析草稿配置，编辑文档，解析并校验整份配置，构建替换用的运行时快照
  （宽松地解析凭据、准备好探测），渲染 diff，通过临时文件加 rename 以 0600 原子写入
  文件，发布快照，调和池子，为新增或改动的账号启动探测。发布之前的任何失败都不改变
  任何东西。
- 文件指纹不匹配会返回 409 并要求重新加载；控制台绝不覆盖编辑器的改动。
- 仅重启生效的设置渲染成只读，并点名需要重启。应用会拒绝改动它们的草稿配置，带一个
  由控制台翻译的 code。
- 只读原始视图从文档生成，每个内联密钥都会打码；原始文件字节从不返回。
- 密钥从不往返：凭据字段只显示来源；新增或轮换 key 只写操作系统的凭据库；文件里存在
  的内联字面量显示为已打码，只能通过另选一个来源来替换。
- `lgw init` 使用同一个原子写入器，而不是原地截断。

### 应用改动

- 重新配置是原地进行的。实时池子从不被替换：一个 Reservation 握着它的克隆，所以换掉
  池子会把真钱花销结算进一个被丢弃的对象。池子增加了 reconcile 和设置 policy 的操作，
  在它现有的锁下执行。
  - 账号按限定 id 做 diff。保留的账号保留闸门、读数、状态、可用时间、窗口起点、上次
    探测和最后一次错误；它们由配置派生的字段（base URL、货币、倍率、限额、metered
    开关）会刷新。
  - 新增的账号以 unknown 进入，异步探测。
  - 被移除的账号会退役：它们不接新工作，对在途尝试仍然可寻址，最后一笔在途占用结算
    后被丢掉。
  - 改一家 provider 的 adapter 或 base URL 会把它名下的账号重置成 unknown，并排队
    重新探测。
  - policy 值在池子锁下更新；探测节奏跟随新值。
  - 学到的价表保留；配置价重新播种、但不覆盖学到的价；档位表被替换；区间账本保留。
  - 相关配置变化时，探测集合和上游 HTTP 客户端会重建；在途尝试继续用它们启动时那个
    客户端。
- 应用通过一个 worker 串行化。文件监视器和控制台提交到同一个队列；内容指纹会压掉
  监视器对控制台自己那次写入的回声。
- 监视器以很短的间隔轮询文件的修改时间、大小和内容指纹。它不需要新依赖，也不会漏掉
  基于 rename 的编辑器保存。
- 仅重启生效的设置：监听地址、账本路径、请求体上限。
- 校验或构建快照失败的应用，什么都不发布、什么都不写。写入之后才失败的应用会报告出来，
  此时文件已经是新的；下次启动就用它。

### HTTP 接口与契约

- 页面是服务端渲染的 HTML：`/`（看板）、`/usage`、`/requests`、`/prices`、`/config`、
  `/keys`、`/doctor`。资源从固定的资源路径前缀提供。自动刷新和动作结果是渲染出的 HTML
  片段，不是 JSON API，这样文案和数字只有一个渲染器。
- 变更请求只接受同源 JSON，必须带 `X-LGW-Console: 1`，并以 HTML 片段作答（整表单提交
  时则是页面级重定向）。处理器和片段都用请求的语言渲染。
- 读是 GET，没有副作用。变更是 POST。没有别的。
- 控制台路由受这些检查保护：loopback 对端检查、`Host` 白名单、存在时的 `Origin` 检查、
  自定义头、JSON content type，以及比代理更小的请求体上限。它们不发 `Access-Control-*`
  头，并带严格 CSP、禁止嵌入、禁止缓存。
- 非 loopback 对端从每一条控制台路径（包括资源）都收到 404。
- 变更用到的状态码：200 已应用/已返回取值，409 冲突或拒绝仅重启生效的改动，422 草稿
  配置无效，503 某个动作的依赖不可用（provider 连不上、凭据库读不了），504 动作超时。
  片段会用当前语言说明是哪种。
- 语言由每个页面和片段上的 `?lang=en|zh` 选择；链接会带上它。顶栏的切换把选择写进浏览
  器的 local storage，并带着参数跳转；没有参数加载的页面会用存下的选择做一次替换。
  不设 cookie。
- 主题是客户端的 `data-theme` 切换，默认浅色，持久化在 local storage，由首屏绘制前的
  一段内联脚本应用。
- 启动时记录监听地址上的控制台 URL。
- `docs/web-ui.md` 里承诺的控制台 API 前缀（/console/api/*）变成变更前缀；响应是
  HTML 片段，那份文档会改成这么说。

### 页面与设计

- 视觉方向是编辑账本式原型：用分隔线而不是卡片，页面和节标题用衬线展示字体，每个数字
  都用等宽表格字体，留白宽裕，一种强调色只留给 metered 的钱；池子表格借用仪表盘原型的
  信息密度，保存/应用控件借用产品控制台原型的常驻工具条。
- 颜色只是第三条通道：状态、过期、漂移和 metered 花销永远同时有文字或形状标记。绿/
  黄/红沿用 CLI 的含义。
- 文案沿用项目的数字量级写法（921.4K、$0.2554）、等宽数字和右对齐金额。
- 图表是服务端用表格所显示的同一批数字生成的 SVG；每张图都带一段简短文字摘要，所以
  不需要悬停。
- 为笔记本和窄窗口做响应式布局；不做手机优先的布局。
- 看板可见时每 10 秒自动刷新，用量页每 30 秒；请求页按需刷新。标签页隐藏时轮询停止。
- 控制台的页面标题、类似 favicon 的标记和空状态都使用项目的词汇；「还没探测过」绝不
  渲染成空池子。
- 写入依赖 JavaScript 来发带自定义头的 JSON 请求；读页面没有它也能渲染。

### 数据与查询

- 看板读内存里的池子快照；渲染时从不探测 provider。
- 用量、请求和价格通过只读连接读账本；它们从不写入。
- 账本 schema 版本 8 只加索引：`requests` 按 provider、model、account 和 coverage 与
  timestamp 的组合，`attempts` 按 provider 和 start time。不重写任何列，也不改金额格式。
- 金额在 Rust 里用 Decimal 聚合，先做带索引的范围扫描；不用浮点求和，各币种的总计分开
  保留。
- 范围是 24h、7d、30d、90d 和 all。尝试级明细受现有的 30 天清理限制；页面会说明这一点。
- 会碰到 provider 的动作（探测、诊断、密钥测试）在请求里同步执行，有界超时；浏览器显示
  运行中状态。

### 打包与依赖

- 资源内嵌在二进制里；一个开发用覆盖开关会从磁盘读它们，这样迭代 CSS 和文案不用重新
  编译。
- 唯一新增的运行时依赖是 `toml_edit`。文件监视器是一个轮询，不是 `notify`；资源服务是
  一个小处理器，不是 `rust-embed` 或 `tower-http`；图表是手绘 SVG，不是图表库。
- 字体来自系统字体栈；不随包发字体，也不从 CDN 加载任何东西。
- `cargo install --path . --locked` 继续产出单个二进制。没有 Node 步骤，也没有 CI 流水线；
  验证命令仍然是 `cargo test`、`cargo clippy --all-targets -- -D warnings`、
  `cargo fmt --check`，再加一次 release 构建。

### 日志

- 一次应用会记录文件路径、它来自控制台还是监视器、改动的区段、任何仅重启生效的拒绝、
  耗时，绝不记录属于密钥的配置值。
- 动作在 info 或 warn 级别记录目标和结果，脱敏规则与 CLI 相同。

## 测试决定

**这里什么算好测试。** 测试像浏览器那样驱动应用，断言外部可见的行为：HTTP 状态和响应体、
之后配置文件的字节、账本里的行、mock 上游收到的请求，以及一个流式请求是否跑完。它们不
调用私有处理器、不检查内部字段、也不对着布局 CSS 做断言。测试按它们断言的行为命名，与
现有测试套件一致。

**接缝。** 只有一条接缝，几乎什么都用它：在真实 loopback 监听器上组装好的 HTTP 应用，
配上临时配置文件、临时账本、内存凭据库和现有的 mock 上游。没有为控制台发明新东西：形状
和今天的代理集成测试一样。loopback 对端规则是唯一的例外：它的判断是对端地址的纯函数，
直接测，因为测试没法对进程开一个真实的非 loopback 连接。

CLI/控制台对等没有第二条接缝：两者调用同一个 operations 模块，CLI 现有测试继续覆盖它的
输出。

**被测模块。** 控制台 HTTP 接口（页面、片段、资源、守卫、头）、应用/重新加载引擎（走同
一个 HTTP 应用，断言文件内容、账本行、流式行为和 mock 上游流量）、配置文档编辑路径（走
校验/应用，断言注释被保留、冲突被拒绝）、用量页使用的账本查询函数（配临时账本），以及
两种语言的渲染。

**先例。** 现有的 router 测试用假后端或 mock 上游搭一个应用，断言状态和响应体；store
测试打开临时账本，断言行；config 测试断言解析和校验结果。控制台测试沿用这些模式。

**测试套件必须钉住的行为。**
- 非 loopback 对端从每一条控制台路径都拿到 404，配没配 `local_key` 都一样。
- 没有自定义头、带外来 `Origin`、带外来 `Host`，或者 content type 不是 JSON 的写入，
  会被拒绝且什么都不改。
- 没有任何控制台响应包含 key 值；通过控制台添加的 key 只能从凭据库读到，绝不会经 HTTP
  读回来。
- 页面和它的片段在两种语言下渲染同样的字段；未知的 `?lang` 回退到英文。
- 无效的草稿配置返回 422，点名出错的字段，不写文件，旧配置继续服务。
- 注释、键顺序和未知键在保存后都还在。
- 用过期文件指纹构建的草稿配置返回 409，更新的那个文件原样不动。
- 仅重启生效的字段渲染成只读，改动它的应用会被一个 code 拒绝。
- 一次配置改动应用时不会丢掉正在流式传输的请求；那个请求用旧快照结算，之后开始的请求
  用新快照。
- 被移除的账号不再接新工作，它在途的尝试仍然结算，账本行保留；新账号在探测成功之前是
  unknown。
- 改一家 provider 的 adapter 会把它名下的账号重置成 unknown。
- 监视器会应用外部的文件改动；控制台自己的保存不会引起第二次应用。
- 失败的应用让上一份快照继续服务，并报告失败。
- 学到的价表和区间账本挺过一次应用。
- 读端点不发起任何 provider 请求（mock 上游的请求计数不变）。
- 用量页的金额总计是精确的，绝不跨币种求和；缺失的窗口会被省略，而不是给零。
- 诊断、探测和密钥测试动作会打到 mock 上游，并把结果呈现出来；超时返回 504 和一个片段。
- 代理测试套件和 CLI 测试套件在机械的模块拆分过程中始终保持绿色。

**不自动化。** 浏览器布局、主题切换和文案语气在开发期间用浏览器工具人工检查；仓库里没有
JavaScript 测试框架，本规格也不新增一个。

## 范围之外

- 对控制台的远程或局域网访问、登录、会话、cookie、RBAC 和 TLS。
- 从控制台编辑仅重启生效的设置；它们仍然是改文件加重启。
- 从控制台跑 `lgw init`。
- Websocket、服务器发送事件（SSE）和流式的实时 tail。
- 按会话的花费分析和会话浏览器。
- 自定义主题、内嵌字体、英文和简体中文之外的语言。
- 对 `/v1` 请求、响应或鉴权契约的任何改动，包括 `/v1/usage`。
- 读端点发起 provider 调用、浏览 provider 目录、计费端点。
- 持久化的审计日志；记录仍然靠 tracing。
- 账本保留期的改动和金额格式的改动。
- JavaScript 框架、Node 构建步骤，或前端单元测试。
- 文件已经支持的之外的第二配置来源（数据库覆盖层、profile、环境变量覆盖）。

## 补充说明

- 为了选方向做过三个静态原型（编辑账本、夜间值守仪表、产品控制台）；它们是一次性的，不属于
  实现。选定的方向记录在上面。
- `docs/web-ui.md` 写在片段渲染决定之前，实现期间会修订它，以说明 HTML 片段响应、只读的
  仅重启生效字段，以及存在浏览器里的语言/主题选择。
- 控制台是唯一一次刻意反转已记录的非目标；ADR-0001 记录了为什么，以及让它安全的那些
  约束。
- 仓库的双语文案约定（英文为主、简体中文为孪生版本）适用于每个控制台页面和本规格。
- 改动离开本机之前的验证：`cargo test`、`cargo clippy --all-targets -- -D warnings`、
  `cargo fmt --check`、一次 release 构建，以及人工过一遍两种主题、两种语言下的每个
  控制台页面。
