# 15：诊断、探测与账号动作

**要构建什么：** 控制台提供 CLI 的运维动作：诊断（全部检查与失败，双语）、探测一个或全部 Account、带确认地停用 Account、再把它启回来（回到 unknown 直到探测确认）。会摸网络的动作用请求内运行态、有界超时和脱敏后的 provider 错误；探测永远不撤销运维手工停用。`lgw doctor` 与 `lgw accounts` 共用这些操作，输出不变。

**依赖：** 01（把 CLI 拆成按命令的模块）、04（控制台入口壳与最小看板）。

- [ ] 诊断按 CLI 的同样结论报告每一项检查与失败，并按请求语言渲染。
- [ ] 探测单个和探测全部在测试中到达 mock 上游，并在之后更新看板。
- [ ] 停用会先确认，且不会被探测撤销；启用把 Account 置回 unknown，直到探测证明可用。
- [ ] 慢或失败的上游行成超时或脱敏错误片段，而不是卡住的页面。
- [ ] CLI 的 doctor 与 accounts 输出字节不变，并共用这些操作。
- [ ] `cargo test`、`clippy --all-targets -- -D warnings`、`fmt --check` 通过。
