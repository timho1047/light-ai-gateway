# 08：应用 policy 改动到运行中的网关

**要构建什么：** 应用一次 policy 改动可以端到端工作。运维改一个 live 字段、看 diff、点应用：文件以 0600 原子替换，运行中的进程发布新快照并在原地更新池子的 policy 数值，新请求立刻使用新值；在应用之前开始的流式请求继续用旧快照跑完，并按旧价格结算。用更旧文件指纹构建的草稿回 409；改动仅重启生效字段的草稿按名字拒绝；校验失败的改动什么都不变。`lgw init` 使用同一个原子写。

**依赖：** 03（引入 Runtime 快照与请求级配置）、07（校验草稿并展示 diff）。

- [ ] policy 字段在表单里可编辑；应用以 0600 原子写文件，重读文件与草稿一致。
- [ ] 应用期间在途的流式请求用原快照完成；之后开始的请求用新值。
- [ ] 过期指纹回 409 且不碰更新的文件；仅重启生效的改动被拒绝并带错误码。
- [ ] 校验或快照构建失败时，文件与运行中的快照都不变。
- [ ] 同时提交的两次应用最终得到一个一致配置，而不是交错结果。
- [ ] `lgw init` 不会留下半截文件，创建的文件权限为 0600。
- [ ] `cargo test`、`clippy --all-targets -- -D warnings`、`fmt --check` 通过。
